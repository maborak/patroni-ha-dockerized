# Patroni HA Dockerized — Extension Roadmap (v2)

> A phased plan for evolving the lab into a production-ready reference architecture.
> Reviewed against the codebase: every item below names the real files it touches,
> follows existing conventions, and includes a way to verify it worked.

---

## Ground rules (how any extension must be built)

These constraints come from how the repo actually works. Violating them breaks the stack.

1. **Never edit `docker-compose.yml` or `configs/*` directly** — both are generated by
   `scripts/generate_configs.sh` from `templates/*.tpl`. New services go into
   `templates/docker-compose.yml.tpl` (+ generator logic if they depend on node count),
   exactly like the existing etcd/db/pgbadger blocks.
2. **Patroni config is rendered at container runtime** — `patroni/entrypoint.sh` substitutes
   `__VARS__` in `templates/patroni.yml.tpl`. New PostgreSQL/Patroni settings are added there,
   not to any rendered artifact.
3. **New Make targets follow the house style**: thin target, `VAR=value` args converted to
   flags, logic lives in a script under `scripts/<domain>/` (see `dump-db`, `pitr`,
   `switchover-to-remote` in the Makefile for the pattern).
4. **Reuse `scripts/lib/common.sh`** — `get_db_nodes`, `get_db_port`, `get_api_port`,
   `detect_leader`, `detect_leader_api`, `detect_healthy_replica`, `validate_node`.
   Don't reinvent node discovery.
5. **Every new script is `bash -n` clean**; every new wizard/interactive flow gets a
   sandboxed smoke test in `scripts/testing/smoke_test_*.sh` (stubbed `docker`, no daemon —
   see `smoke_test_wizard.sh`). `make smoke-test` must stay green.
6. **Docs parity** (`CONTRIBUTING.md`): new behavior ⇒ update `docs/` + README table rows.
7. **Secrets live only in `.env`** (gitignored). Generated artifacts (`configs/`,
   `docker-compose.yml`) stay gitignored. New credential-like vars get safe defaults in
   `.env.example`.
8. **Optional features are opt-in via `.env`** (e.g. `ENABLE_MONITORING=1`) so the default
   stack stays as lean as today. Prefer Compose `profiles:` for opt-in services.
9. **Dynamic node count**: anything that references `db1..dbN` (HAProxy backends, Backup
   sections, scrape targets, log volumes) must be generated per-node in
   `generate_configs.sh` — copy the `WRITE_SERVERS`/`DB_SECTIONS` loop pattern.

## Phase 1: Observability & Monitoring (Foundation)

**Goal:** See cluster health, replication lag, query performance, and resource use in real
time; alert before users notice. Effort: M overall · ~1–2 weeks.

| # | Task | Concrete implementation | Effort |
|---|------|------------------------|--------|

| 1.2 | **Grafana with pre-provisioned dashboards** | `grafana/provisioning/datasources/prometheus.yml` + `grafana/provisioning/dashboards/*.json` (committed). Start from community IDs 9642 (Patroni), 455 (PG), then customize for this topology. Service under `profiles: [monitoring]`, `GRAFANA_PORT`, `GRAFANA_ADMIN_PASSWORD` in `.env` | M |
| 1.3 | **Alertmanager + rules** | `prometheus/alerts.yml` (committed, mounted ro). Alerts mirror what `check_stack.sh` already validates: no leader >30 s, replica lag bytes/time, etcd quorum loss, WAL archive backlog, last-successful-backup age, disk >80 %, PgBouncer saturation, pgBadger collection stale. Routes: Slack/webhook via `ALERTMANAGER_*` vars | M |
| 1.4 | **Log aggregation (live tail)** | `vector` (or `promtail`) container reading the shared `dbN_logs` volumes (they're already mounted into `pgbadger` — same pattern), shipping JSON logs to Loki. *Complements* pgBadger (analytics) with live search/retention. | 1.5 | **Failover-history metric** | Small recording rule / textfile collector fed by a cron script `scripts/checks/export_patroni_state.sh` (writes leader name, epoch, member states to `node_exporter/textfile/`) → gives "time since last failover" panels | L |

`GRAFANA_ADMIN_PASSWORD`.

**Deliverables:** `prometheus/`, `grafana/`, template+generator changes, `docs/monitoring.md`.

## Phase 2: Security Hardening

**Goal:** Encrypt in transit, close known plaintext/TOFU gaps, rotate credentials safely.
Effort: M–L · can run parallel to Phase 1.

| # | Task | Concrete implementation | Effort |
|---|------|------------------------|--------|
| 2.1 | **Fix SSH host-key checking (quick win)** | Today every SSH hop uses `-o StrictHostKeyChecking=no` (`archive_command` and `restore_command` in `templates/patroni.yml.tpl`, `ssh_command` generated in `backup.conf`). Extend `scripts/utils/setup_ssh_keys.sh` to also `ssh-keyscan backup dbN` into `ssh_keys/known_hosts` on first run and mount it read-only where needed; drop the `no` flags | S |
| 2.2 | **TLS for PostgreSQL** | `scripts/security/generate_certs.sh` (openssl): local CA + server certs with SAN `dbN`, output to gitignored `tls/` (mirrors `ssh_keys/` lifecycle). `TLS_ENABLED=1` gates: entrypoint substitutes `ssl_cert_file/ssl_key_file` params; `pg_hba` block switches `host` → `hostssl`; HAProxy backend `ssl`; PgBouncer `client_tls_sslmode`. Verify: `psql "sslmode=verify-full"` | M |
| 2.3 | **TLS for etcd + Patroni REST API** | etcd peer/client certs wired through the generated `command:` in `docker-compose.yml.tpl`; `ETCD_HOSTS` switches to `https://`. Patroni `restapi` gains cert + `authkey` (or basic auth) so `/switchover`, `/failover` aren't anonymous | M |
| 2.4 | **Backup encryption at rest** | Backup has no native encryption — don't fake it. Add a `restic` (or WAL-G w/ SSE) sidecar on the `backup_repo` volume, scheduled by the existing supervisord; `RESTIC_REPOSITORY`/`RESTIC_PASSWORD` in `.env`. `make backup` optionally triggers snapshot after success | M |
| 2.5 | **Credential rotation** | `make rotate-passwords WHAT=postgres\|replicator\|stats`: ALTER ROLE on leader → regenerate `userlist.txt` (`make generate`) → reload PgBouncer → update `.env` → verify replication (replicator password requires per-replica `ALTER ROLE` + restart). Runbook in `docs/security.md` | M |
| 2.6 | **Vault integration (optional)** | Compose profile `vault`: dev-mode Vault + init container that fetches secrets at startup and materializes them for entrypoints; `.env` keeps only Vault address/token. High value only for shared/team deployments | L |
| 2.7 | **Network segmentation** | Split `patroni_network` into `dcs_net` (etcd↔db), `backup_net` (db↔backup), `app_net` (haproxy/pgbouncer↔db); document required flows in `docs/architecture.md`. Pure template/generator change | S |

**Deliverables:** `scripts/security/`, `tls/` (gitignored), template changes,
`docs/security.md`, `.env.example` §10 SECURITY.

**Verify:** with `TLS_ENABLED=1`: `openssl s_client` to :5551 shows cert;
etcd health OK over TLS; `make check` green; `make switchover NEW_LEADER=db2` still works
(proves Patroni API auth didn't break ops scripts — update `common.sh` curl calls if needed).

## Phase 3: Resilience & Chaos Engineering

**Goal:** Prove the HA claims with repeatable failure drills, not anecdotes.
Effort: M · builds on Phase 1 (alerts) but works standalone.

| # | Task | Concrete implementation | Effort |
|---|------|------------------------|--------|
| 3.1 | **Chaos suite** | `scripts/chaos/` — one script per fault, all sourcing `lib/common.sh`: <br>• `kill_leader.sh` (docker kill → poll `detect_leader_api`)<br>• `kill_etcd.sh N` (quorum math assertion)<br>• `partition_node.sh NODE` (`docker network disconnect/connect` + reconnect timer)<br>• `fill_disk.sh NODE PCT` (fallocate on the data volume, cleanup trap)<br>• `pause_barman.sh` (WAL backlog drill)<br>Each prints PASS/FAIL verdict + timing; `make chaos [TEST=…]` runs all | M |
| 3.2 | **Failover benchmark** | `scripts/testing/benchmark_failover.sh`: continuous write probe through HAProxy :5551 (`INSERT` with monotonic id) → kill leader → measure (a) time-to-new-leader, (b) time-to-first-successful-write, (c) lost ids (expect 0). Appends result row to `reports/failover_benchmark.tsv`. `make benchmark-failover [ROUNDS=3]` | S |
| 3.3 | **Stress during failover** | Wire existing `stress_test_db.sh` into 3.2: `make benchmark-failover WITH_STRESS=1` starts pgbench-style load first, benchmarks under load | S |
| 3.4 | **Backup verification (restore test)** | `scripts/backup/verify_backup.sh BACKUP_ID`: ephemeral `postgres:$POSTGRES_VERSION` container mounting `backup_repo`, runs `barman restore` → starts PG in single-user/recovery → sanity queries → checksum spot-check vs `pg_dump`. `make verify-backup [BACKUP_ID=latest]`. This is the only proof a backup is restorable | M |
| 3.5 | **Scheduled PITR drill** | Cron-friendly non-interactive wrapper around 3.4 + `perform_pitr.sh --dry-run`, writing to `reports/pitr_drill_<ts>.log`; sample crontab documented in `docs/runbooks.md` | S |

**Deliverables:** `scripts/chaos/`, extended `scripts/testing/`, `docs/chaos.md`,
CI wiring below.

**CI (GitHub Actions):** `.github/workflows/ci.yml` — `bash -n` over `scripts/**`,
`shellcheck` (advisory), `make smoke-test`, and `generate_configs.sh` + `docker compose config -q`
with a dummy `.env` (catches template regressions without a daemon). Chaos suite stays
local/manual (needs Docker), but its PASS/FAIL format makes results pasteable into PRs.

**Verify:** `make chaos TEST=leader-kill` passes with promotion <30 s and 0 lost writes;
`make verify-backup` restores latest backup successfully.

## Phase 4: Operational Tooling & Automation (Day-2)

**Goal:** Cut toil: migrations, scaling, upgrades, environments, cloning.
Effort: item-dependent · pick per need.

| # | Task | Concrete implementation | Effort |
|---|------|------------------------|--------|
| 4.1 | **Schema migration runner** | Flyway container (profile `migrations`), migrations dir bind-mounted from `./migrations`; `make migrate [ARGS="info"]` execs it against HAProxy :5551. Optional pre-flight `make backup` hook (`MIGRATE_BACKUP_FIRST=1`) | S |
| 4.2 | **Formalized scaling** ✅ *done* | `make scale REPLICAS=5` → `scripts/ops/scale_cluster.sh` (grow: config regen + join + health wait + backup image rebuild; shrink: auto-switchover off doomed leader, typed confirmation, volume + Backup cleanup; `DRY_RUN`, `YES`, `SKIP_WAIT`, `TIMEOUT`). Sandboxed smoke test in `scripts/testing/smoke_test_scale.sh` | S |
| 4.3 | **Rolling restart / minor-version updates** | `make rolling-restart`: per node (replicas first, leader last via switchover): stop → start → wait `streaming`/`running` → next. Safe for image bumps within same PG major | S |
| 4.4 | **Major-version upgrade (16/17)** | Semi-automated `scripts/ops/upgrade_pg.sh TARGET=16` following the documented sequence: full backup → `pg_upgrade --link` on stopped leader datadir → bump `POSTGRES_VERSION` → reinit replicas one-by-one → verify. Ship as guarded runbook script + `docs/upgrades.md`; refuse to run without fresh `verify-backup` pass | L |
| 4.5 | **Multi-environment** | `ENV=staging` support in `generate_configs.sh`: prefer `.env.$ENV` over `.env`, set `COMPOSE_PROJECT_NAME=patroni-$ENV` for volume/network isolation; `make status ENV=` aware. Wizard learns to write `.env.<name>` | M |
| 4.6 | **Clone stack for dev/test** | `make clone NAME=clone1 [BACKUP_ID=…]`: second compose project (own ports/volumes) bootstrapped from a Backup restore — reuses 3.4 machinery. Cheap disposable environments | M |
| 4.7 | **WAL-G / object-storage archiving** | Profile `walg` as alternative/complement to rsync-WAL-to-Backup: `WALG_S3_PREFIX`, incremental base backups, off-host copies. Keeps Backup PITR intact; adds cloud durability | L |
| 4.8 | **pgBadger long-term archive** | After each parse cycle, tar + ship report/raw window to S3/restic repo (`PGBADGER_ARCHIVE_*` vars); extends the existing `collect.sh` cycle | S |

**Deliverables:** `migrations/`, `scripts/maintenance/rolling_restart.sh`,
`scripts/ops/upgrade_pg.sh`, `docs/operations.md` index, `.env.example` §11 TOOLING.

**Verify:** `make scale REPLICAS=5` joins two new streaming replicas unattended;
`make rolling-restart` completes with `make check` green; migration demo applies + rolls back cleanly.

## Phase 5: Multi-Host & Cloud-Native Evolution (Future)

**Goal:** Escape the single-host boundary. Only start when a real requirement exists —
each option is a different product, not a feature.

| # | Option | Notes | Effort |
|---|--------|-------|--------|
| 5.1 | **Docker Swarm** | Nearest neighbor to current design: `deploy/swarm/stack.yml` with placement constraints, overlay net, Docker secrets replacing `.env` interpolation. Existing entrypoints survive unchanged | L |
| 5.2 | **Kubernetes (Helm)** | StatefulSet per PG node + PodDisruptionBudgets, etcd via operator or Bitnami chart, Services for rw/ro split, CronJob backups (or CloudNativePG/Baron as prior art). Honest take: at this point you adopt CloudNativePG rather than port Patroni | XL |
| 5.3 | **Operator pattern** | Custom controller reconciling replicas/version/backups/TLS. Only justified if 5.2 lands and team wants GitOps UX | XL |

**Deliverables:** `deploy/swarm/` or `deploy/k8s/` + `docs/deployment.md`.

## Recommended order

```
Phase 1 (Observability) ──┐
                          ├─► Phase 3 (Chaos) ──► Phase 4 (Day-2 ops)
Phase 2 (Security) ───────┘                        └─► Phase 5 (only if required)
```

**First three weeks (concrete):**

1. **Week 1 — quick wins:** CI workflow (bash-n/shellcheck/smoke-test/compose-config) +
   2.1 SSH known_hosts fix + Prometheus/postgres_exporter/Grafana MVP (1.1–1.2).
2. **Week 2 — prove HA:** `make chaos` leader-kill + etcd tests, `benchmark-failover`
   (3.1–3.3), Alertmanager rules (1.3) firing on those drills.
3. **Week 3 — production posture:** TLS for PostgreSQL + Patroni REST (2.2–2.3),
   backup verification (3.4), rotation runbook (2.5).

## Success criteria

| Milestone | Measurable criterion |
|-----------|----------------------|
| Observability MVP | All Prometheus targets up; leader-kill visible in Grafana; alert fires ≤60 s |
| Security baseline | `TLS_ENABLED=1` stack passes `make check`; no `StrictHostKeyChecking=no` left in repo; backups encrypted at rest |
| Chaos validated | `make chaos` all-green: promotion <30 s, zero lost writes, quorum holds single-etcd loss |
| Backups trustworthy | `make verify-backup` succeeds on latest backup; nightly drill log exists |
| Day-2 ready | `scale`, `rolling-restart`, `migrate` complete without manual `docker exec`; docs updated |
| Regression safety | `make smoke-test` green on every PR; CI validates generated compose |

## Non-goals

- Becoming a multi-host production deployment system as-shipped (single-host scope stays).
- Replacing Backup/Patroni with CloudNativePG etc. inside this repo — that's Phase 5 territory.
- Touching the wizard UX before Phase 4.5 (multi-env) lands.
